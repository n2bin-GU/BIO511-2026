Introduction

By this point in the course you have used the command line, Git, Python, files, functions, plotting, and several genomics workflows. This practical connects those experiences by asking a deeper question:

What kind of computational problem is this, and what algorithmic idea makes it possible at genomic scale?

We will focus on algorithms that appeared inside tools already used in the course:

Earlier workflow Tool Algorithmic idea in this tool
Taxonomic classification Kraken2 k-mers, indexes, and lowest common ancestors
Read mapping1 BWA exact seeds, local alignment, and genome indexes
Functional annotation2 Prokka BLAST-like sequence search and profile HMMs

The purpose is not to reproduce these production tools. Instead, we will build small examples that expose their most important ideas.

Learning Objectives

By the end of this practical, you should be able to:

  • Explain why a simple algorithm may fail when applied to millions of reads
  • Describe how k-mers can represent and classify sequences
  • Explain the difference between exact search, local alignment, and heuristic seed-and-extend search
  • Explain why genome indexes make read mapping scalable
  • Connect Kraken2, BWA, and Prokka to the algorithmic ideas they use
  • Compare exact and heuristic approaches in terms of speed, memory, and sensitivity
  • Write pseudocode for a realistic genomics problem before writing code

Where Does the Word Algorithm Come From?

The word algorithm comes from the name of the Persian mathematician Muhammad ibn Musa al-Khwarizmi, who lived around the 9th century. His name was later Latinized in Europe as Algoritmi.

One reason his name became so strongly connected with algorithmic thinking is that his mathematical works described general, repeatable procedures for solving problems. In his work on al-jabr, he gave systematic methods for solving linear and quadratic equations, which are polynomial equations of degree 1 and degree 2. The important idea was not just finding one answer, but describing a method that could be followed again and again for similar problems.

Over time, this name became associated with step-by-step methods for doing calculations. That meaning eventually developed into the modern word algorithm: a precise set of instructions for solving a problem.

In short:

al-Khwarizmi -> Algoritmi -> algorithm

The word algebra also comes from the title of one of his mathematical works, which included the Arabic word al-jabr.

Warm-up: Algorithmic Thinking as Planning

Before we look at genomics algorithms, let us start with a smaller planning problem. Planning is a useful way to think algorithmically because it forces us to define a starting state, a goal state, and the actions that can move us from one state to another.

This warm-up is adapted from a planning example in the Artificial Intelligence Core Course at Saarland University, Germany.

Imagine this toy problem:

Question: What is the shortest sequence of valid actions that gets us from the starting state to the goal state?

Jane starts at home. A virus problem must be solved at location F. She can solve it in one of two ways:

  • buy disinfectant and use it at location F
  • buy both a mask and toilet paper, then use them at location F

However, she first needs to withdraw money from the cash point before buying anything.

In planning language, we can describe the problem like this:

Planning concept Meaning in this example
Initial state Jane is at location A
Goal state The virus problem is solved
Action Something Jane can do, such as walk, withdrawMoney, or buyDisinfectant
Preconditions What must already be true before an action can happen
Effects What changes after the action is performed
Plan A sequence of actions that reaches the goal
Optimal plan A valid plan with the lowest cost, often the fewest actions

For example, the action buyDisinfectant can be written as:

Action: buyDisinfectant
Preconditions:
    at(G)
    hasMoney
Effects:
    hasDisinfectant
    no longer hasMoney

One valid plan is:

walk(A, C)
withdrawMoney
walk(C, G)
buyDisinfectant
walk(G, C)
walk(C, F)
useDisinfectant

This is algorithmic thinking in a very direct form. We are not just listing commands randomly. We are reasoning about what must be true before each step, what each step changes, and whether the final goal has been reached.

The same logic appears in bioinformatics workflows:

Planning idea Genomics workflow analogue
Initial state Raw sequencing reads
Goal state Interpretable biological result
Action Run quality control, trim reads, map reads, assemble contigs, annotate genes
Preconditions Required input files, software, indexes, databases, or parameters
Effects New output files, filtered reads, alignments, assemblies, variant calls
Plan The workflow connecting all steps
Optimal plan A workflow that is accurate, reproducible, efficient, and appropriate for the question

For example:

raw FASTQ files
-> quality control
-> trimming
-> read mapping or assembly
-> variant calling or annotation
-> biological interpretation

This is why algorithmic thinking matters. A workflow is not only a list of tools. It is a plan where every step has inputs, assumptions, outputs, and consequences.

Why Genomics Needs Efficient Algorithms

Imagine mapping 10 million reads to a bacterial reference genome by testing every read at every possible genome position:

For each read:
    For each position in the genome:
        Compare the read with the reference at that position

The instructions are correct, but the amount of work is enormous. Real genomic data also contain sequencing errors, repeated regions, contamination, and genuine biological variation.

Bioinformatics tools therefore rely on several recurring strategies:

  • Break sequences into smaller pieces, such as k-mers or seeds
  • Build indexes so that the program does not repeatedly scan the complete database
  • Score candidate answers rather than treating every match as equally plausible
  • Use heuristics when checking every possible answer would be too slow
  • Represent uncertainty when the data do not support one certain answer

Essential Vocabulary

Concept Meaning in practice
Input Data given to an algorithm, such as reads or a reference genome
Output The result, such as a taxon or mapping position
State Information remembered while the algorithm runs
Score A number used to compare candidate answers
Search space All answers the algorithm could consider
Index A data structure that makes later searches faster
Exact algorithm Returns an exact answer under its model
Heuristic A faster strategy that may miss some possible answers
Complexity How runtime or memory grows as the input grows

Core Idea 1: k-mers and Taxonomic Classification

Exact Matching

Exact string matching asks where a short pattern occurs in a longer sequence.

Genome:  TTGATGCCCATGAAATGA
Pattern:    ATG

A direct algorithm slides the pattern across the genome and compares one window at a time:

For each possible start position:
    Extract a window with the same length as the pattern
    If the window equals the pattern:
        Report the position

This is manageable for a short sequence, but repeatedly scanning a large reference database is expensive.

Representing Sequences with k-mers

A k-mer is a sequence word of length k. Sliding a window across ATGACC with k = 3 produces:

ATG, TGA, GAC, ACC

k-mers are useful because they turn long sequences into smaller searchable units. They appear in classification, error correction, mapping, and many other genomics tasks.

The value of k creates a trade-off:

  • Small k: more matches, but many are non-specific
  • Large k: more specific, but more sensitive to sequencing errors

k-mers are used in many genomics tools:

  • read error correction
  • genome assembly
  • metagenomic classification
  • contamination checks
  • genome distance estimation
  • fast pre-filtering before alignment

The key idea is that long biological sequences can be represented as collections of shorter sequence words.

Python example: naive search vs indexed k-mer search

def naive_map(read, reference):
    hits = []
    comparisons = 0
    for start in range(len(reference) - len(read) + 1):
        window = reference[start:start + len(read)]
        comparisons += 1
        if window == read:
            hits.append(start)
    return hits, comparisons

def build_kmer_index(reference, k):
    index = {}
    for start in range(len(reference) - k + 1):
        kmer = reference[start:start + k]
        if kmer not in index:
            index[kmer] = []
        index[kmer].append(start)
    return index


def indexed_map(read, reference, index, k):
    hits = []
    comparisons = 0
    seed = read[:k]
    candidate_positions = index.get(seed)
    for start in candidate_positions:
        window = reference[start:start + len(read)]
        comparisons += 1
        if window == read:
            hits.append(start)
    return hits, comparisons

reference = "TTGATGAGCCCCATGAGATGA"
reads = ["ATGAG"]
k = 3

# Build once and reuse for every read.
index = build_kmer_index(reference, k)

total_naive = 0
total_indexed = 0

for read in reads:
    naive_hits, naive_checks = naive_map(read, reference)
    indexed_hits, indexed_checks = indexed_map(read, reference, index, k)
    total_naive += naive_checks
    total_indexed += indexed_checks
    print("Read:", read)
    print("Naive:", naive_hits, "comparisons:", naive_checks)
    print("Indexed:", indexed_hits, "comparisons:", indexed_checks)

print("Total naive comparisons:", total_naive)
print("Total indexed comparisons:", total_indexed)

# output:
# Read: ATGAG
# Naive: [3, 12] comparisons: 17
# Indexed: [3, 12] comparisons: 3
# Total naive comparisons: 17
# Total indexed comparisons: 3

From k-mers to Kraken2-style Classification

In the WGS workflow, Kraken2 classified reads taxonomically. Conceptually, its database connects sequence words to taxa. If the same sequence evidence occurs in several taxa, that evidence can be assigned to their lowest common ancestor, or LCA.

read
-> extract k-mers
-> look up matching taxa
-> assign ambiguous evidence to an LCA
-> combine the evidence into a classification

Real Kraken2 uses minimizers and highly optimized data structures. The following teaching implementation uses complete k-mers so that the logic remains visible.

Runnable Example: k-mer Index and LCA Classification

def _kmers(sequence, k):
    """Return every k-mer in order, including repeated k-mers."""
    if k <= 0 or k > len(sequence):
        return []
    list_kmers =[]
    for i in range(len(sequence) - k + 1):
        list_kmers.append(sequence[i:i + k])
    return list_kmers


def _lowest_common_ancestor(taxa, taxonomy):
    """Return the most specific ancestor shared by all taxa."""
    if len(taxa) == 0:
        return None
    # Build a lineage for each taxon.
    lineages = []
    for taxon in taxa:
        ancestors = []
        while taxon is not None:
            ancestors.append(taxon)
            taxon = taxonomy[taxon]
        lineages.append(ancestors)
    # Find the first ancestor shared by every lineage.
    for ancestor in lineages[0]:
        shared = True
        for lineage in lineages:
            if ancestor not in lineage:
                shared = False
                break
        if shared:
            return ancestor
    return "root"


def build_kmer_taxon_index(reference_sequences, k):
    """Connect every reference k-mer to the taxa containing it."""
    index = {}
    for taxon, sequence in reference_sequences.items():
        list_kmers = _kmers(sequence, k)
        for kmer in list_kmers:
            if kmer not in index:
                index[kmer] = set()
            index[kmer].add(taxon)
    return index


def classify_read(read, k, kmer_index, taxonomy):
    """Let matching k-mers vote for taxa or shared ancestors."""
    votes = {}
    list_kmers = _kmers(read, k)
    for kmer in list_kmers:
        matching_taxa = kmer_index.get(kmer, set())
        if matching_taxa:
            taxon = _lowest_common_ancestor(matching_taxa, taxonomy)
            votes[taxon] = votes.get(taxon, 0) + 1

    return votes


taxonomy = {"root": None, "Bacteria": "root", "E_coli": "Bacteria", "S_enterica": "Bacteria"}
references = {"E_coli": "ATGC", "S_enterica": "ATGA"}

k = 3
kmer_index = build_kmer_taxon_index(references, k)
results = classify_read("ATGC", k, kmer_index, taxonomy)
print(results)

What the Functions Do

Part of the k-mer/LCA example Purpose
Extract words with _kmers() Take every overlapping word of length k from a sequence, including repeated words
Build kmer_index with build_kmer_taxon_index() Connect each reference word to the taxa containing it; a set records each taxon only once per word
Find matching_taxa in classify_read() Look up a read word in the index; an absent word gives an empty set and no vote
Find a shared label with _lowest_common_ancestor() Assign the most specific ancestor shared by all matching taxa; a word matching one taxon keeps that taxon’s label
Update votes in classify_read() Add one vote to the selected label for each matching read word
Return the sorted votes Put labels with more votes first; equal counts remain tied

Here, k = 3 sets the word length for both index construction and read lookup. In ATGC, the shared word ATG gives one vote to Bacteria, and TGC gives one vote to E_coli. The returned list is [('Bacteria', 1), ('E_coli', 1)]: a summary of the evidence, with tied counts.

What to Notice
  • The expensive reference processing happens once when the index is built.
  • Dictionary lookup replaces repeated scanning of every reference.
  • Shared sequence evidence produces a less-specific taxonomic answer.
  • Changing k changes sensitivity and specificity.

Core Idea 2: Seed-and-Extend Sequence Search

Biological Problem: Where Could This Read Match?

In a read-mapping workflow, we want to find where a sequencing read fits in a longer reference sequence. A read may contain a changed base, so we want to allow a small number of differences.

A seed is a short piece of the read that must match the reference exactly. Once we find a seed, we compare the surrounding reference window with the complete read. This is the seed-and-extend idea.

For our small example:

Reference: GGG ATGACCATGATT ACGCCAAGCTTT
Read:          ATGACCATGATT
First seed:    ATGA

The spaces in the reference line separate the surrounding DNA from the matching window. The first seed starts at reference position 3, counting from zero. Comparing the complete read at that position gives zero mismatches.

The Algorithm

For each seed in the read:
    Find every exact occurrence of that seed in the reference
    Use the seed's position to place the complete read
    Compare the read with the reference window
    Keep the placement if it has few enough mismatches
Return the retained placements

Runnable Example: Simplified Seed-and-Extend

This is the original seed-and-extend example. It searches two reference fragments and returns candidate positions. The extension step counts base differences in a window of the same length as the read; it does not handle insertions or deletions.

def seed_and_extend(query=None, target=None, k=None, max_mismatches=None):
    """Return candidate placements supported by an exact seed."""
    hits = set()

    for query_start in range(len(query) - k + 1):
        seed = query[query_start:query_start + k]
        target_start = target.find(seed)

        while target_start != -1:
            placement_start = target_start - query_start
            placement_end = placement_start + len(query)

            if placement_start >= 0 and placement_end <= len(target):
                target_window = target[placement_start:placement_end]
                mismatches = sum(
                    query_base != target_base
                    for query_base, target_base in zip(query, target_window)
                )

                if mismatches <= max_mismatches:
                    hits.add((placement_start, target_window, mismatches))

            target_start = target.find(seed, target_start + 1)

    return hits


database = {
    "gene_A": "GGGATGACCATGATTACGCCAAGCTTT",
    "gene_B": "TTTCCCGGGAAATTTCCCGGG"
}

query = "ATGACCATGATT"

for name, sequence in database.items():
    for hit in seed_and_extend(query=query, target=sequence, k=4, max_mismatches=2):
        print(name, hit)

Expected output:

gene_A (3, 'ATGACCATGATT', 0)

The result means: a candidate was found in gene_A, starting at position 3, with reference window ATGACCATGATT and 0 mismatches. No candidate was retained for gene_B.

What the Function Does

Part of seed_and_extend() Purpose
Extract seed Take a word of length k from the read
Find target_start Locate that word in the reference; .find() returns -1 when no occurrence remains
Calculate placement_start Work backward from the seed to the start of the complete read
Count mismatches Compare each read base with the corresponding reference base
Store a hit in hits Keep an acceptable placement; the set avoids reporting it repeatedly when several seeds support it
Return the sorted hits Put placements with fewer mismatches first

Here, k = 4 sets the seed length. max_mismatches = 2 allows at most two base differences across the complete read window. A placement must have both an exact seed and an acceptable mismatch count to be returned.

Try One Changed Base

Change the read to ATGACCATGACT and allow one mismatch:

query = "ATGACCATGACT"
print(seed_and_extend(query, database["gene_A"], k=4, max_mismatches=1))

Expected output:

[(3, 'ATGACCATGATT', 1)]

The first seed still matches, but the complete read differs from the reference window at one base. The placement is retained because one mismatch is allowed. If max_mismatches is changed to zero, the result is an empty list.

Summary

We used two concrete examples to practice algorithmic thinking:

  • k-mer classification: break a read into words, look them up, and collect taxonomic evidence.
  • Seed-and-extend search: find exact short matches, compare the surrounding sequence, and retain candidate placements with few mismatches.

For each example, identify the inputs, follow the steps, inspect the output, and explain what that output means biologically.
