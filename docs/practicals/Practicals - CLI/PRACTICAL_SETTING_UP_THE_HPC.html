Practical: Setting up the HPC

BIO511 Genomics - from first login to a working Vera environment

Author

Kaisa Thorell, Tor Kling, Vahid Atabaigielmi

Published

September 1, 2026

1 Why this practical?

This practical takes you from having a newly created C3SE/Vera account to a usable day-to-day HPC workflow.

It assumes you have already read the introductory lecture on HPC clusters and understand the basic difference between a login node, a compute node, shared storage, and the SLURM scheduler.

The examples below use the following course account details:

CID / Vera username: jonsnow
Project:             C3SE408-25-2
Cluster:             Vera
Login nodes:         vera2.c3se.chalmers.se
Learning objectives

By the end of this practical, you should be able to:

  • Activate and test your Chalmers CID password.
  • Connect to Vera through SSH.
  • Understand when VPN is required.
  • Configure a convenient SSH alias.
  • Verify project membership and storage quota.
  • Navigate safely on a login node.
  • Find software using the module system.
  • Submit, monitor, and inspect a simple SLURM job.
  • Connect VS Code to Vera using Remote SSH.
  • Know what should and should not be done on a login node.

2 1. Account activation and password

When C3SE creates a Vera account, the username is normally your Chalmers ID, or CID.

For this practical:

CID: jonsnow

If the CID is newly created, set its password through Chalmers MyAccount:

https://myaccount.chalmers.se

If you already had the same CID, your normal CID password should work.

A newly created CID can take some time to propagate through Chalmers systems. If login fails immediately after activation, this does not necessarily mean the password is wrong.

Password safety

Never put your CID password inside a shell script, SLURM script, Quarto document, Git repository, or plain-text notes.

3 2. VPN: when is it needed?

Vera is directly reachable from the Chalmers and GU networks.

When you are outside those networks, for example at home, connect to the Chalmers VPN before trying to use Vera.

The typical connection path is:

Your laptop
   |
   | Chalmers VPN, when off campus
   v
Vera login node
   |
   | SLURM
   v
Compute node

If SSH waits for a long time and eventually gives:

ssh: connect to host ... port 22: Operation timed out

check the VPN first.

C3SE’s connection documentation is available at:

https://www.c3se.chalmers.se/documentation/connecting/

4 3. First SSH connection

Open Terminal on your laptop.

Use Vera2 login nodes:

ssh jonsnow@vera2.c3se.chalmers.se

The first time you connect, SSH may ask whether you trust the host key:

Are you sure you want to continue connecting (yes/no/[fingerprint])?

If the hostname and fingerprint match the C3SE documentation, type:

yes

Then enter your CID password.

A successful login looks similar to:

[jonsnow@vera2 ~]$

This tells you:

  • You are logged in as jonsnow.
  • You are currently on the vera2 login node.
  • ~ means your home directory.
Do not run heavy analyses here

vera2 is shared login node. Use it for navigation, editing, file transfer, preparing jobs, submitting jobs, and checking jobs.

Large analyses belong on compute nodes through SLURM.

5 4. Make SSH easier with an alias

Typing the full hostname every time is unnecessary.

On your local laptop, create or edit:

~/.ssh/config

For example:

mkdir -p ~/.ssh
nano ~/.ssh/config

Add:

Host vera
    HostName vera2.c3se.chalmers.se
    User jonsnow

Save the file.

Now you can connect with:

ssh vera

C3SE documents this SSH configuration approach here:

https://www.c3se.chalmers.se/documentation/connecting/ssh/

6 6. Confirm your project allocation

After logging into Vera, run:

projinfo

For this course account, the output should contain something similar to:

Project                Used[h]         Allocated[h]      Queue
   User
---------------------------------------------------------------
C3SE408-25-2              16.00                 5000       vera
   aryastark              16.00
   jonsnow                0.00

The important lines are:

Project:       C3SE408-25-2
Allocation:    5000 core-hours
Queue:         vera
Your user:     jonsnow

projinfo is useful whenever you want to check which projects you can charge jobs to.

7 7. Check your storage and quota

Run:

C3SE_quota

Example output for the course user jonsnow:

[jonsnow@vera2 ~]$ C3SE_quota

Home: /cephyr/users/jonsnow
  Space used:     0.0GiB       Quota:      30GiB
  Files used:          9       Quota:      60000

Path: /cephyr/NOBACKUP/groups/n2bin_gu
Proj: c3se408-25-2
  Space used:   370.5GiB       Quota:    5000GiB
  Files used:      48652       Quota:     500000

------------------------------------------

This output shows two storage areas. The Home area belongs to the individual user and has a 30 GiB space quota. The project storage is located at /cephyr/NOBACKUP/groups/n2bin_gu and is associated with project c3se408-25-2. In this example, the project area has a 5000 GiB quota. The Space used lines show storage consumption, while the Files used lines show how many filesystem entries are currently counted against each file quota.

This shows storage areas available to your account and how much space is being used.

Also learn these basic commands:

pwd
ls
ls -lah
cd ~
du -sh .

Typical Vera paths can include locations such as:

/cephyr/users/<CID>/Vera
/cephyr/NOBACKUP/groups/<project-or-group>/

The exact project/group path available to you should be confirmed from C3SE_quota or the course instructions.

7.1 Home versus project storage

Use your home directory for:

  • Small scripts.
  • Configuration files.
  • Notes.
  • Small test inputs.

Use project/group storage for:

  • FASTQ files.
  • BAM/CRAM files.
  • Genome references.
  • Larger result directories.
  • Shared datasets.

Do not fill the home directory with large sequencing datasets.

8 10. Software modules

Vera is a managed HPC environment. You normally do not use sudo or apt-get to install system software.

Software is commonly provided using modules.

Start with:

module list

Search for software:

module spider Python

or:

module spider samtools

Load a module only after identifying the version you need:

module load <module-name>

Check what is loaded:

module list

Remove currently loaded modules:

module purge

For reproducibility, load required modules inside your SLURM job script.

9 11. Inspect the scheduler

Vera uses SLURM.

Check the cluster/partition state:

sinfo

The STATE column summarizes what is happening on the nodes. The most useful states to recognize are:

idle   = available for new jobs
alloc  = fully allocated/running jobs
mix    = partially occupied
down   = unavailable
drain  = being taken out of service
resv   = reserved

Check your jobs:

squeue -u $USER

Before submitting your first job, this will probably show no jobs.

Useful SLURM commands include:

sbatch job.sh
squeue -u $USER
scancel JOBID
sacct -j JOBID

10 14. Disconnect safely

When a job was submitted with sbatch, it belongs to SLURM and keeps running after you disconnect.

You can leave Vera with:

exit

Closing your laptop does not stop a normal batch job.

You do not need tmux simply to keep sbatch jobs alive.

11 16. Connect VS Code to Vera with Remote SSH

VS Code can edit files directly on Vera using the Remote - SSH extension.

This is convenient for scripts, Quarto files, configuration files, and small development tasks.

C3SE warns that heavy or long-running VS Code activity should not consume login-node resources. For heavier interactive work, C3SE recommends running VS Code/code-server on compute resources through its portal when appropriate.

C3SE documentation:

https://www.c3se.chalmers.se/documentation/software/development/vscode/

From your laptop:

ssh vera

Do not troubleshoot VS Code until normal SSH works.

Open VS Code on your laptop.

Open Extensions and install:

Remote - SSH

from Microsoft.

If you already created this local file:

~/.ssh/config

with:

Host vera
    HostName vera2.c3se.chalmers.se
    User jonsnow

VS Code can use it directly.

Alternatively:

  1. Press Cmd+Shift+P.
  2. Run Remote-SSH: Add New SSH Host....
  3. Enter:
ssh jonsnow@vera2.c3se.chalmers.se
  1. Select your normal SSH configuration file, usually ~/.ssh/config.

Press Cmd+Shift+P and run:

Remote-SSH: Connect to Host...

Choose:

vera

A new VS Code window should open.

The lower-left corner should indicate that VS Code is connected to the remote host.

In the remote VS Code window, select:

File -> Open Folder

For example:

/home/.../hpc_practical

or simply browse from your home directory.

For a real course project, open the appropriate directory in project storage.

Open:

Terminal -> New Terminal

The prompt should look like a Vera prompt, for example:

[jonsnow@vera2 ...]$

That terminal is remote.

The same login-node rule applies: use it for light work and job submission, not large analyses.

11.1 Python interpreter in VS Code

If you load a Python module on Vera:

module load <Python-module>
which python

copy the resulting interpreter path.

In VS Code:

  1. Press Cmd+Shift+P.
  2. Choose Python: Select Interpreter.
  3. Choose Enter interpreter path if needed.
  4. Paste the path returned by which python.

Because module environments can change, keep your real computational environment reproducible in scripts/job files rather than depending only on VS Code state.

11.2 VS Code troubleshooting

If VS Code Remote SSH becomes stuck after changing configuration:

  1. Press Cmd+Shift+P.
  2. Search for Remote-SSH: Kill VS Code Server on Host....
  3. Select vera.
  4. Reconnect.

Also verify that the VPN is still connected when you are off campus.

12 20. Login node versus compute node checklist

12.1 Safe on a login node

  • cd, ls, pwd
  • Editing scripts
  • Git operations of reasonable size
  • Small file inspection
  • module spider
  • projinfo
  • C3SE_quota
  • sbatch
  • squeue
  • sacct
  • Short/light testing

12.2 Submit through SLURM

  • Genome assembly
  • Read mapping over real datasets
  • Large BLAST searches
  • Large Python/R analyses
  • Long jobs
  • Memory-intensive jobs
  • Parallel CPU jobs
  • GPU workloads

If you are unsure, submit it as a job rather than running it for a long time on vera2.

15 25. Take-home workflow

The practical setup can be summarized as:

CID/password
      |
      v
VPN when off campus
      |
      v
SSH / VS Code Remote SSH
      |
      v
vera2 login node
      |
      +--> project + storage checks
      +--> edit scripts
      +--> transfer files
      |
      v
sbatch
      |
      v
SLURM scheduler
      |
      v
compute node
      |
      v
results in persistent storage
      |
      v
inspect / rsync / download results

The goal is not simply to “log in to Vera”. The goal is to develop a reproducible workflow where the login node is used to prepare work and SLURM is used to execute computation safely on compute nodes.
