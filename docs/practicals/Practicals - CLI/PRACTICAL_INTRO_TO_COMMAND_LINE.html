1 Introduction

Doing bioinformatics often necessitates the handling of very large files, with complex structure and dense matrices. This makes them often unwieldy to pretty much impossible to handle in traditional GUI-based analysis tools (such as Excel), and as such we rely on more rudimental and lightweight file handling systems such as bash-based command line enviroments that allow us to interact with our computer on a more fundamental level.

Typically the first thing you encounter on opening a new terminal instance is:

user@computer:~$

This is the terminal prompt where you’ll be able to issue commands to the computer, with the syntax (“grammar” of the code) of your command prompts often using the following structure:

user@computer:-$ command -option my_object

# or you may have more advanced command prompts
user@computer:-$ command -threads 2 -output $My_Directory_Variable/ -prefix New_file_ -accessoryfile Additional_file my_object | nextcommand -cvfz New_file_my_object.tar.gz

Imagination (and resources, complexity, optimization…) sets the limit of what you can do in the CLI

If you’re further curious on the history of shell and the command line.

Learning Objectives

By the end of this practical, you should be able to:

  • Navigate the file system using cd and ls
  • Create and manipulate directories with mkdir
  • Create, copy, move, and delete files using touch, cp, mv, and rm
  • View file contents using cat, head, and tail
  • Search within files using grep
  • Display text using echo
  • Edit text using sed
  • Tie these commands together using pipes
  • Plan your computational workflow using pseudocode

2 Making, Navigating and finding things in your directories

2.1 Understanding Your Location (pwd and ls)

Before we start creating new things in our directory its a good idea to get a grip on your whereabouts within the working directory

  • pwd: Print working directory - shows your current location
  • ls: List contents of directories
  • command --help: Show help-documentation for a command, very useful for lookups when we need a command to do something specific

Find your current location and explore the directory

# Run pwd
pwd

# Run ls
ls

# Setting the -l flag for ls will give you a more detailed view of the contents of the directory
ls -l

# Run with the help flag to get the documentation for the command
pwd --help

You can also use the man command to get a more detailed manual for a command, which is especially useful for more complex commands with many options. For example, you can run man ls to see the manual for the ls command. If you have an internet connection, it is also possible to search for command documentation online, for example by searching for “ls command linux” in your preferred search engine.

Exercise: Hidden Files and Directories

Some programs make “hidden” directories and files in you directories that fulfill important functions for the program, these are usually denoted by a . in front of the name. To list these hidden files and directories we need a special option flag for the lscommand.

  • Use the –help flag and look through the documentation to find the right flag for ls to show hidden files and folders.
Expected output (no peeking!)

The flag for ls to show hidden files and directories is -a. You can use it like this:

ls -a

# or as a list
ls -la

2.2 Making and Changing Directories (mkdir and cd)

Since the command line interface (CLI) can quickly become cluttered, we organize our work into directories. Similar to the folders on windows or macOS, directories act as containers that create a hierarchy of files and subdirectories. This is especially important in bioinformatics, where we often deal with large datasets and multiple analysis steps that need to be organized for reproducibility and clarity.

  • mkdir: Create new directories
  • cd: Change directory
  • Special directories: . (current), .. (parent), ~ (home), / (root)

Create and navigate a genomics project structure

# Create a main directory for this exercise
mkdir CLI_intro

# Navigate into it
cd CLI_intro

# Create additional directories within the main directory
# This can be done in multiple ways 
# For example, you could make multiple directories in one command:
mkdir Escherichia
cd Escherichia
mkdir coli hermanni fergusonii

# Check your structure
ls -la

# Navigate around and try the special directory short-hands
cd ~        # Go home
cd ..        # Go back to previous directory
Additional Command: tree [Optional]

There is another very useful command for visualising directories called tree, which will print the directory structure in a tree-like format. This is especially useful for visualizing complex project structures. If you don’t have it installed, you can usually install it via your package manager (e.g., sudo apt install tree on Ubuntu/WSL2 or brew install tree for MacOS).

  • Try running tree in your current directory to see the structure of your project. You can also use tree -L 2 to limit the depth of the tree displayed.
  • Sometimes we only want to see the directory structure without all the files, if you have time then look for the flag that allows you to do this in the tree documentation.

Tree is very useful for visualizing complex project structures, but it is not always installed by default and we might also not always need the amount of information it provides. Sometimes a simple ls command is enough to get a good overview of the directory structure.

3 File Creation and Manipulation

Now that we have an introduction to navigating our workspace, let’s learn how to create and manage files. In bioinformatics, you’ll constantly be creating, copying, moving, and organizing data files - from raw sequencing data to analysis results. While in a typical file explorer, you may drag and drop files as you please, in CLI, these operations require deliberate commands.

3.1 Text manipulation (echo, touch, less, cat)

Before we start with file manipulation, we’ll first introduce text files the old school way via echo and touch, as well as some commands to view the contents of files.

  • touch: Create empty files
  • echo: Print text provided in the prompts
  • less: View file contents in a scrollable format
  • cat: Concatenate and display file contents

Handling text in CLI

# First, lets use echo in the ye olde intro to programming way
echo "Hello World!"

# Not the most exciting, but we can use it to add text to files via > 
# Create a file using touch 
touch test_file

# Then add some text to the file 
echo "Some_text" > test_file

# You can view the contents of the file using `cat` or `less`
cat test_file # Prints to the terminal
less test_file # Opens a scrollable instance of the file
# To exit less, press `q` on your keyboard

# Now add some more text to the next line in the file
# To add to a file you simply extend the > operator to >> 
echo "Some_more_text" >> test_file

# Now lastly, try to wipe the file with some new text
# This removes all the previous text and replaces it with the new text, but we will see that 
# In the next section.
echo "New_text" > test_file

3.2 File Manipulation (cp, mv, rm)

Now let’s create some mock files that we will use downstream in the analysis, and learn how to use commands to copy, rename and remove files

  • mv: Rename the absolute path of a file (moving it)
  • cp: Copy a file
  • rm: Remove a file (Irreversible, be careful!!)

Create sample files and practice file operations

# Create some more directories to store everything in 
mkdir -p raw_data backups

# Make a test file to work with
echo "This is a test file for practicing file manipulation." > test_file.txt
echo "It contains some sample text for testing purposes." >> test_file.txt

# Copy files (backup your data!)
cp test_file.txt raw_data/
cp test_file.txt test_file_backup.txt

# Move files to organize your project
mv test_file_backup.txt backups/

# remove files (be careful, no undo!)
rm test_file.txt

# rm can also be used with flags to remove directories and their contents
rm -r backups/

4 Viewing and Searching File Contents (head, tail, grep)

One of the most powerful aspects of the command line is being able to quickly peek into files without opening them in a text editor. You already know less and cat by now, but often we dont need to view the entire file.This is especially useful when working with large genomics files where you only need to see a portion of the content or search for specific patterns. The cat’s constiuent parts (its head and tail) are very useful for quick overviews of file contents, while grep is a powerful tool for searching through files for specific patterns.

  • head: Show first lines of a file
  • tail: Show last lines of a file
  • grep: Search for patterns within files

Now let’s work with file contents using the mock genomics data you just created.

Create sample genomics files and explore them


# View entire files
cat sequences.fasta

# View only the first 2 sequences (headers + sequences)
head -n 4 sequences.fasta

# View the last 2 lines of expression data
tail -n 2 expression_data.csv

# Search for specific genes or functions
grep "lacZ" sequences.fasta
grep "^>" sequences.fasta  # Find all sequence headers

# Count how many sequences we have
grep -c ">" sequences.fasta

# A very useful flag is the -A or -B flag, which allows you to show lines after or before a match. 
# For example, if we want to see the sequence for lacZ, we can use the -A flag to show the line after the match:
grep -A 1 "lacZ" sequences.fasta

# Search expression data case-insensitively
grep -i "PROTEIN" expression_data.csv

# Show line numbers with matches
grep -n ">" sequences.fasta

5 Processes, Input and Output

When we perform computational tasks, a simplified pipeline can can be broken down into three main components: input, process, and output. Understanding these components is crucial for effectively using command line languages, and forms the basis for future workflows where we integrate scripts and proper programming languages (C, Python, R, etc.) into our analysis pipelines. For command line operations, we can think of input as the data we provide to a command, the process as the command itself that manipulates or analyzes the data, and the output as the result produced by the command.

5.1 Text Editing with sed (Stream Editor)

If we want to make edits to lines or whole files, without having to rewrite whole files, we can use the sed command. sed sees input as a stream of text, and allows us to perform operations on it, such as find-and-replace, deletion, or insertion of text while the program reads the input line by line. This is especially useful for large files where opening them in a text editor would be impractical. The output of sed is printed to the terminal by default, but it can also be redirected to a new file with > or edited inplace with the -i flag.

  • sed (stream editor): Allows for edits of existing text and replacing/modifying it with new text

Use sed for find-and-replace operations

# Create a sample file for sed operations
echo "This is some old-text that needs to be replaced." > input_sed.txt

# Now run sed to replace all instances of 'old-text' with 'new-text'
sed 's/old-text/new-text/g' input_sed.txt > output_sed.txt
cat output_sed.txt

# Note that sed does not write to the original file unless you use the -i flag (in-place)
sed -i 's/old-text/new-text/g' input_sed.txt
cat input_sed.txt

# It can also be used to delete lines containing a specific pattern
sed '/plasmid/d' gene_annotations.csv > chromosomal_only.csv
cat chromosomal_only.csv
When to use sed and when to use an editor (nano, vim, etc.) (Optional)

While you’ve probably used text editors like “Notes” on you computer or more advanced word processors like Word, command line environments are typically not adequate for heavy GUI (Graphical User Interface) based applications. Instead we often use more scaled down, but still powerful, editors like nano or vim that work well in the command line environment. These editors allow for more complex text manipulation and editing, but they require a bit of a learning curve to use effectively. In this course we focus on using IDEs (Integrated Development Environments) for writing scripts and code, but for quick edits on the HPC for example, text editors like nano and stream editors like sed are very useful to learn.

Examples of when to use sed vs a text editor:

Use Case sed Text Editor
Quick find-and-replace in a file Yes No
Delete lines containing a specific pattern Yes No
Edit a single line in a file Yes Yes
Correct variables or parameters in a script Yes (but more work) Yes
Write a new script or program No Yes
Note

sed is one of the more dynamic tools used in the command line, and they way we have introduced it here is quite simple, as a tool for small find and replace operations. For a more in depth look at sed and its capabilities, check out some other resources like this. It is also, technically, a programming language

5.2 Putting it all together with pipes (|)

Here’s where the command line really starts to shine! Pipes allow you to chain commands together, passing the output of one command as input to another. This creates powerful, flexible operations that can process data in more advanced ways with just a single line of code. It also saves us time by not having to run multiple executions before we get our desired output.

  • |: Pipe - pass output from one command to another

Chaining commands together will be key later in this course section, when we start working on scripts.

Create files and use pipes for complex operations

# Skip the header and show only first 2 data rows
grep -v "Gene_ID" gene_annotations.csv | head -n 2

# We can combine commands to edit specific lines as well 
# Use it to remove all the underscores from the sequence headers in sequences.fasta
grep '^>' sequences.fasta | sed 's/_/ /g'

# Classic examples of pipes use some additional commands we havent introduced yet
# For example, we can use cut, sort and uniq to find unique gene names in the gene_annotations.csv file
cut -d',' -f1 gene_annotations.csv | sort | uniq

# One thing to keep in mind is that pipes need a "stream" of input/output.
# To understand this, test and see what happens when we direct output to file in the middle of a pipe chain
cut -d',' -f1 gene_annotations.csv | sort > sorted_genes.txt | uniq

6 Pseudocode and Thinking in Processes

In this introduction to command line we’ve learned how to navigate the filesystem, create and manipulate files, and use pipes to combine commands. Now let’s take a step back and introduce how we can plan our computational workflows using pseudocode. Pseudocode is a way to outline your coding and analysis in plain language (mixed with some correct code-formulations) before translating them into actual commands or scripts. This helps you organize your thoughts and sketch out the logic of your analysis without getting bogged down in syntax.

We can plan pipes in pseudocode for example like this:

Pseudocode for a change of a gene name in a file:
[Read file | Find gene name & Replace with new name | Write to new file]

A bad way to write this pseudocode would be to write it like this:
[Read the file and find the gene name and replace it with the new name and write to a new file]

A less good way, but at this point you might as well write the actual command, would be to write it like this:
[cat gene_file.csv | sed 's/old_gene_name/new_gene_name/g' > updated_gene_file.csv]

which in bash would be implemented like this:

cat gene_annotations.csv | sed 's/RNA_polymerase_beta_subunit/RNA_polymerase_B/g' > updated_gene_annotations.csv

6.1 Pseudocode for Scripts

But this becomes all the more important as we start to write scripts and programs, where we need to think about the flow of data and the sequence of operations. By writing pseudocode first, we can ensure that our analysis is well-structured and that the logic is sound before we start coding. For this the format of the pseudocode is a bit subjective, but it should clearly outline the steps of the analysis, including the input data, the processing steps, and the expected output. It should also be easy to read and understand, and make sense in the context of the target language syntax.

Pseudocode for the overarching parts of a script to analyze some genomics data

Input: 
  sequences.fasta
  reference_genome.fasta

Steps:
  read files
  align sequences to reference genome
  filter alignments based on quality
  count number of aligned sequences
  write results to output file

Output:
  alignment_results.txt

Its also a good idea to outline pseudocode for the key steps of the analysis, such as the main function used to align sequences, or the function used to filter alignments. This helps to ensure that each step of the analysis is well-defined and that the code is organized in a logical manner. Simple pseudocode for the “count number of aligned sequences” step could look like this:

for each aligned sequence:
  if alignment quality is above threshold:
    count as valid alignment
    valid_alignments += 1
  else:
    discard alignment
    Print text to terminal: "Alignment discarded due to low quality"

Print text to terminal: "Total valid alignments: " + valid_alignments

Key Takeaways
  • Organization matters, good directory structure keeps your files findable, we’ll learn more about this in the next practical!
  • Pipes are powerful, chain commands to create complex operations, making your work more efficient
  • Use sed for quick edits, but know when to use a text editor instead
  • Always check your work, use ls, cat, head to verify operations
  • Be cautious with rm, no undo in command line!
  • Utilize pseudocode to plan your analysis, it helps to clarify your thoughts and structure your code logic
Tips for Bioinformatics CLI Work
  • Use Tab for autocompletion
  • Use ↑ arrow to recall previous commands
  • Use Ctrl+C to stop running commands
  • Always backup important files before major operations
  • Start directory names with numbers for quick autocomplete: 01_script.sh, 02_analysis.sh
